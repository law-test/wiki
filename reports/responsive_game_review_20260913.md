# 반응형·게임·검수 반영 경로 검토

검토일: 2026-09-13. 기준 커밋: `eca5bf42c05347c2af2e847862149c93c1da8b16`.

이 문서는 자동 검증, 로컬 브라우저 확인 및 운영 문항 수정 확인을 정리한다. 운영 DB 문항 7개 수정과 재조회는 완료했으며, HTML·CSS 등 웹 파일 배포는 아직 진행 전이다. 아래 브라우저·운영 DB 결과는 통합 검증 담당자의 실제 확인 기록을 반영했다.

## 자동 검증 실행

저장소 루트에서 실행한다. Node.js 24와 Python 3.13에서 확인했으며 추가 패키지는 필요 없다.

```text
node --test tests/game-regression.test.cjs
python -m unittest discover -s tests -p "test_question_review_overrides.py" -v
git diff --check
```

이번 검토 결과: 게임 23개, 검수·import 21개 통과. HTML 내부 실행 스크립트 7개와 별도 `assets/supabase.min.js` 라이브러리 1개의 문법 검사, 변경 차이 공백 검사도 통과했다. 실행 코드가 아닌 `application/json` 블록 1개는 스크립트 문법 검사 대상에서 제외했다.

게임 검증은 가짜 시계·문항 응답·화면 요소를 사용한다. 재시작 타이머 중복, 입력창의 O/X 오작동, 숨긴 화면의 시간 경과, 지연 응답의 라운드 오염, 판례 빈칸 중복 채점, 종료 중복 저장, 이전 한글 입력 콜백의 간섭, 좁은 게임판에서 객체가 잘리는 문제를 확인한다. 게임판 폭 220·264·320·360·640·1000px 및 폭 변경을 계산으로 검증한다.

검수 검증은 합성 문항과 임시 파일만 사용한다. 반복 적용, 비활성 유지, 원자료 누락·중복·원문 변경 시 중단, 입력 자료 불변성, SQL 생성, SQL/REST import 연결을 확인한다. REST 검증에서는 네트워크 호출을 금지한다.

## 연결 구조

- 검색은 실제 폼 제출을 사용하고 검색 표시만 변경한다. 댓글 입력 폼이나 게임 엔진을 재생성하지 않는다.
- 변시탐험은 게임판 아래에 왼쪽 이동·점프·오른쪽 이동 버튼과 터치 설명을 항상 표시한다. 버튼 높이는 최소 48px이며 시작 전·종료 후에는 비활성화된다. 버튼에 초점이 있을 때 Enter/Space와 문서 단축키가 중복 실행되지 않는지 실제 이벤트 처리 함수로 검증했다.
- `assets/responsive-fixes.css`는 기존 첫 스타일 블록 뒤에서 읽으며 기존 `data-game-panel`, `hidden`, `section.art.on` 구조를 유지한다. 게임 화면 확인 함수와 충돌하는 표시 규칙은 이번 코드 검토에서 발견하지 못했다.
- SQL 생성기와 REST 업로더는 문항 키를 확정한 뒤 `apply_final_reviews()`를 호출한다. 등록된 검수 대상이 누락되거나 원문이 달라지면 파일 출력·DB 초기화·업로드 이전에 중단한다.
- 검수 레지스트리 기본 경로는 `reports/question_review_overrides_20260913.json`이다. 파일이 없으면 조용히 건너뛰지 않는다. `--review-overrides`로 다른 검수 파일을 명시할 수 있다.
- `active=false`는 SQL INSERT, SQL 충돌 갱신, REST 행 생성에서 그대로 보존한다. 검수 수정은 `(bank, source_pid, source_variant)`로 적용하며 생략한 필드는 유지한다.
- `generate_review_sql()`은 실행하지 않는 SQL 생성 함수다. 생성 SQL은 행 잠금·정확한 원문 확인·단일 트랜잭션을 사용하며 이미 동일한 수정값인 행은 다시 갱신하지 않는다.

## 브라우저 확인

Edge에서 로컬 수정안을 확인했다. 가로 폭 320·360·390·768·1024·1440px에서 각각 7개 게임 준비 화면을 확인해 총 42개 조합을 점검했다. 별도로 844×390px 가로 화면에서 7개 게임을 확인했다. OX·법조윤리·타자·조문 빈칸·판례 빈칸·산성비·변시탐험의 실제 실행도 확인했다.

- 검색 버튼 클릭, Enter 제출, 검색 초기화 후에도 입력 중인 메모가 유지됐다.
- 변시탐험 조작 버튼은 위 6개 가로 폭에서 모두 화면 안에 들어왔다. 실측 높이는 최소 48px였고, 320px에서는 문구가 줄바꿈되며 62.5px였다. 왼쪽 버튼 클릭 후 위치 25%, 오른쪽 버튼에서 Enter 후 위치 50%, 점프 동작의 클래스 적용을 확인했다. 버튼 높이는 기존 스타일보다 우선하도록 `.clarity-fix` 선택자를 적용했다.
- 320px에서 로그인 대화상자, 게시판 작성 폼, 뉴스 화면의 가로 넘침이 없었다.
- 로컬 검증 서버는 쓰기 요청을 차단하고 실제 읽기 전용 RPC 호출을 허용했다. 로그인 창 표시는 확인했으나 회원 가입이나 OAuth 요청을 실제 전송하지 않았다.

## 운영 문항·신고 확인

운영 DB 문항 7개를 갱신한 뒤 관리자 조회로 수정값을 확인했다. 6개는 활성 상태에서 검수 내용을 반영했고, 신고 #7에 해당하는 1개는 `active=false`로 비활성화했다.

- 실제 공개 채점 RPC에서 활성 문항 6개의 정답·해설·참고 문구·수정 지문이 검수 레지스트리와 정확히 일치했다. 법조윤리 문항은 태그도 일치했다.
- 비활성화한 신고 #7 문항은 같은 공개 채점 경로에서 빈 배열(`[]`)을 반환해 제외됨을 확인했다.
- 신고 #2~#6은 `resolved`, #7은 `needs_review`로 정리했다. 기존 테스트 신고 #1은 `open` 상태를 유지했다.

## 검증 범위와 남은 확인

브라우저 확인은 Edge의 화면 크기 조절을 사용했다. 실제 휴대전화와 iOS Safari, 모바일 한글 키보드는 시험하지 않았다. 로그인 확인은 창 표시까지만 수행했으며 가입·OAuth 완료 흐름은 검증하지 않았다. 자동 검증 자체는 실제 브라우저나 Supabase 권한 검증을 대체하지 않는다. 문항 테스트는 법리나 정답의 정확성을 판정하지 않으며 검수 담당자가 확정한 수정값의 전달·보존을 확인한다.

웹 파일 배포가 남아 있으므로 운영 사이트에서 수정된 화면과 조작을 다시 확인해야 한다. 운영 DB 확인은 위 문항과 신고 및 공개 채점 응답에 한정되며 전체 권한 정책을 검증한 것은 아니다.

작성된 검수 레지스트리 7개 항목은 형식 검증과 SQL 문자열 생성을 통과했다. 신고 #5의 법조윤리 생성기에서 생성되는 base/twin1 두 행은 실제 생성 함수와 최종 행 변환 함수를 메모리에서 대조해 재적용을 확인했다. 나머지 CLAT 5개 행을 포함한 최종 비공개 원자료 전체의 재수입은 이번 검토에서 실행하지 않았다. 향후 수입 때는 검수 대상 누락·중복·원문 불일치를 검사한 뒤 진행한다.

최종 코드 차이 검토에서 게임 입력·타이머 변경, 검색 수정, 반응형 CSS 및 검수 적용 경로 사이의 치명적인 충돌은 발견하지 못했다.
